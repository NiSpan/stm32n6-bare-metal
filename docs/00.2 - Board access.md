## The ST-LINK on USB

The board connects to the PC through the on-board **ST-LINK/V3** (USB-C). Linux sees it as a USB device from STMicroelectronics:

```sh
lsusb | grep -i st
# Bus 001 Device 002: ID 0483:3754 STMicroelectronics STLINK-V3
```

`0483` is ST's USB vendor ID, `3754` the product ID of this ST-LINK/V3 model.

## udev rule: permission to use it

By default, Linux creates USB device nodes (`/dev/bus/usb/<bus>/<device>`) readable and writable by **root only**. Tools like OpenOCD or STM32CubeProgrammer run as my normal user, so without a rule they fail with a permission error.

**udev** is the Linux service that creates device nodes when a device is plugged in. A **udev rule** tells it how to set them up. ST ships one per ST-LINK version; for the ST-LINK/V3 it is `49-stlinkv3.rules`:

```
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="3754", \
    MODE:="0666", \
    SYMLINK+="stlinkv3loader_%n"
```

| Part                              | Meaning                                              |
| --------------------------------- | ---------------------------------------------------- |
| `SUBSYSTEMS=="usb"`, `ATTRS{...}` | Match: a USB device with ST's vendor and product ID  |
| `MODE:="0666"`                    | Read and write for every user                        |
| `SYMLINK+=...`                    | Extra name for the device under `/dev`               |
| `49-` prefix                      | Rules run in file name order                         |

Install it and reload udev (the rule file comes with STM32CubeProgrammer, see below):

```sh
sudo cp ~/STMicroelectronics/STM32Cube/STM32CubeProgrammer/Drivers/rules/49-stlinkv3.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Check (bus and device numbers come from `lsusb`):

```sh
ls -l /dev/bus/usb/001/002
# crw-rw-rw- 1 root root ...      rw for everyone
```

The Docker container uses the same device node (passed in with `devices:` in [Docker](<00.1 - Docker.md>)), so the rule on the host is what lets OpenOCD in the container open the ST-LINK.

> [!note]
> The rule stays in `/etc/udev/rules.d/` even if STM32CubeProgrammer is uninstalled.

## STM32CubeProgrammer (optional)

ST's tool for connecting to STM32 chips: read and write memory and registers, program internal and external memories, option bytes. It has a GUI and a CLI (`STM32_Programmer_CLI`), documented in [STM32CubeProgrammer command lines](https://dev.st.com/stm32cube-docs/prog/2.23.0/en/docs/markup/CubeProg_Command_Lines.html).

I installed it at the start as a quick way to check that I can talk to the board and read its memory, before having any other tools. On the host only, not in Docker.

Later OpenOCD does the same job for debugging, but CubeProgrammer is needed again for:

- **Flash boot**: its `STM32_SigningTool_CLI` adds the header the boot ROM requires
- **External flash** programming with ST's loaders
- **OTP fuses**: the N6 has no flash for option bytes; permanent configuration is stored in one-time programmable fuses, read and written through the **BSEC** block (RM0486, BSEC section and OTP fuse tables). One use is OTP124 (HCONF1): its HSLV bits tell the chip that an I/O supply runs at 1.8 V, so pins on it reach full speed. CubeProgrammer has an OTP tab for this ([How to program the OTP fuse bits in the STM32N6](https://community.st.com/stm32-mcus-60/how-to-program-the-otp-fuse-bits-in-the-stm32n6-148456)).

> [!warning] OTP fuses
> A fuse can be written only once. Setting the HSLV bits while that supply is at 3.3 V damages the chip. Read the current value first, and check the board's supply voltages in UM3417 before writing anything.

Install: downloaded the Linux `.zip` from [st.com](https://www.st.com/en/development-tools/stm32cubeprog.html), extracted it, ran the installer. It installs to `~/STMicroelectronics/STM32Cube/STM32CubeProgrammer` (uninstaller in the same folder).

It is not on the `PATH` by default. In fish:

```fish
fish_add_path ~/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin
```

Check:

```
$: STM32_Programmer_CLI --version
      -------------------------------------------------------------------
                        STM32CubeProgrammer v2.23.0                  
      -------------------------------------------------------------------

STM32CubeProgrammer version: 2.23.0 

```
